# 千 QPS 单体运行环境评估

> 目标：当前项目（PC 管理端 + 微信小程序）运行流畅，支持约 **1000 次/秒** 并发请求，采用单体部署、自购云服务器。

## 一、当前技术栈与流量特点

| 组件 | 技术 | 说明 |
|------|------|------|
| 后端 | Spring Boot 3、Java 21、Tomcat、Druid、MyBatis-Flex | 已配置 Tomcat max 800 线程、accept-count 1000 |
| 数据库 | PostgreSQL 16（pgvector） | 单库，Druid 当前 maxActive=20 |
| 缓存 | simple（内存） | 可选 Redis 插件，未启用时无独立缓存服务 |
| PC 端 | Vue3 静态资源 | 由 Nginx 提供或同机部署 |
| 小程序 | 直连后端 API | 不占独立服务，与 PC 共用后端 |

**流量假设**：1000 QPS 指「到达后端的 HTTP 请求」约 1000 次/秒；其中约 30%～50% 会落库（300～500 次/秒到 PostgreSQL），其余走缓存或静态。

---

## 二、推荐方案概览

- **千 QPS 要稳**：建议 **应用与数据库分离**（两台机）。
- **先省成本、接受 500～800 QPS 更稳**：可 **单机一体**（一台机跑 Nginx + Java + PostgreSQL），千 QPS 为上限、偶发峰谷可能略吃紧。

下面按「推荐方案」和「最低成本方案」分别给配置。

---

## 三、推荐方案：应用机 + 数据库机（约 1000 QPS 稳定）

### 3.1 应用服务器（跑 Nginx + 后端 JAR）

| 项目 | 建议 |
|------|------|
| **CPU** | 4 核～8 核（8 核更从容） |
| **内存** | 8 GB～16 GB |
| **系统盘** | 40～80 GB SSD |
| **数据盘** | 可选 50～100 GB SSD（存上传文件、日志） |
| **带宽** | 5～10 Mbps 固定带宽（或按量 20 Mbps 峰值） |
| **系统** | Linux（如 CentOS 7/8、Ubuntu 20/22、Alibaba Cloud Linux） |

**用途**：  
- Nginx：反向代理 + 静态资源（PC 前端打包后的 dist）。  
- 后端：单实例 `java -jar geek-admin.jar`，JVM 堆建议 4～6 GB（如 `-Xms4g -Xmx6g`）。

### 3.2 数据库服务器（仅跑 PostgreSQL）

| 项目 | 建议 |
|------|------|
| **CPU** | 4 核 |
| **内存** | 8 GB～16 GB（16 GB 更稳） |
| **系统盘** | 40～80 GB SSD |
| **数据盘** | **强烈建议** 100 GB+ SSD，单独挂载到 PostgreSQL 数据目录 |
| **带宽** | 内网互通即可（同地域 1～5 Mbps 内网通常够） |
| **系统** | Linux |

**用途**：  
- 仅安装 PostgreSQL 16，跑项目库 `bt10`。  
- 千 QPS 下约 300～500 次/秒到 DB，4 核 8 GB 可支撑，16 GB 可加大 `shared_buffers` 提升性能。

### 3.3 可选：Redis（建议在千 QPS 时启用）

若启用项目内 **Redis 插件**（会话/缓存）：

| 项目 | 建议 |
|------|------|
| **部署** | 可与应用同机（2 核 2 GB 足够），或使用云厂商 Redis 托管（1 GB 实例） |
| **内存** | 1～2 GB |

不买独立 Redis 也可跑，但千 QPS 时 Redis 能明显减轻 DB 压力、会话更稳。

---

## 四、最低成本方案：单机一体（约 500～800 QPS 更稳，千 QPS 为上限）

一台机器同时跑：**Nginx + 后端 JAR + PostgreSQL**。

| 项目 | 建议 |
|------|------|
| **CPU** | 8 核 |
| **内存** | 16 GB |
| **系统盘** | 80 GB SSD |
| **数据盘** | 100 GB SSD（DB + 上传文件 + 日志） |
| **带宽** | 5～10 Mbps 固定（或按量 20 Mbps 峰值） |
| **系统** | Linux |

**注意**：  
- JVM 堆建议 6～8 GB，给系统与 PostgreSQL 留 8～10 GB。  
- 千 QPS 时 CPU 会到 70%～90%，适合「平均 500～800 QPS、峰值 1000」的场景；若长期稳定 1000 QPS，仍建议拆成「应用 + 数据库」两台。

---

## 五、应用与数据库配置调优建议（千 QPS）

### 5.1 后端（application-data.yml / 生产环境）

- **Druid 连接池**：当前 `maxActive: 20` 偏小，建议改为 **50～80**（与 PostgreSQL `max_connections` 协调，留一部分给管理/监控）。  
- **JVM**：  
  - 应用机 8 GB：`-Xms4g -Xmx4g` 或 `-Xmx6g`；  
  - 应用机 16 GB：`-Xms6g -Xmx6g`。  
- **Tomcat**：现有 `max: 800`、`accept-count: 1000` 可保留，无需再放大。

### 5.2 PostgreSQL（数据库机）

- **max_connections**：建议 100～200（应用池 50～80 + 预留）。  
- **shared_buffers**：8 GB 机可设 2 GB，16 GB 机可设 4 GB。  
- **work_mem**：可适当调大（如 32～64 MB）以优化复杂查询。  
- 数据目录、WAL 放在 **SSD** 上，避免高 IO 时成为瓶颈。

### 5.3 Nginx（应用机）

- 静态资源走 Nginx，反向代理到后端 8080。  
- `worker_connections` 可设 4096～8192，一般默认即可支撑千 QPS 前端静态。

## 六、云服务器选型参考（按推荐方案）

| 角色 | 配置示例 | 参考（以阿里云/腾讯云为例） |
|------|----------|------------------------------|
| **应用机** | 4～8 核 8～16 GB，80 GB SSD，5 Mbps | 通用型/计算型，约 300～600 元/月 |
| **数据库机** | 4 核 8～16 GB，100 GB SSD，内网 | 同规格，约 300～500 元/月 |
| **合计** | — | 约 **600～1100 元/月**（按量或包年更便宜） |

单机一体（8 核 16 GB + 100 GB SSD）约 **400～700 元/月**，但千 QPS 时更吃紧，建议作为过渡，稳定后拆成两台。

---

## 七、小结

- **目标**：PC + 微信小程序、约 1000 QPS、单体部署。  
- **推荐**：  
  - **应用机**：4～8 核、8～16 GB、SSD、5～10 Mbps。  
  - **数据库机**：4 核、8～16 GB、SSD（数据盘 100 GB+）。  
  - 可选：同机或托管 **Redis** 以稳会话与缓存。  
- **最低成本**：单机 8 核 16 GB + SSD，适合 500～800 QPS 更稳、千 QPS 为峰值；长期千 QPS 建议应用与数据库分离。  
- **必做调优**：Druid `maxActive` 50～80、JVM 堆 4～6 GB、PostgreSQL `max_connections` 与 `shared_buffers` 按内存配置。

按上述采购与调优后，可满足「运行流畅、支持 PC 与微信小程序、约千 QPS 并发」的单体运行环境需求。
