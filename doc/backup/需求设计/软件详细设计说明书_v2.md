## 1. 项目全景与架构愿景

### 1.1 核心设计哲学：溪水模型与AI原生

本项目的架构蓝图建立在"宏大单体（Majestic Monolith）"与"AI原生（AI-Native）"的双重基石之上，融合道家智慧，通过"成长导航、知识共生、价值连接"三大核心能力，助力用户生命绽放。

#### 1.1.1 溪水模型设计哲学

项目采用"溪水模型"作为核心用户体验设计原则：
- **感知阶段**：价值触点展示，动态流淌的"价值流"
- **浸润阶段**：生态位识别，个性化成长路径
- **融入阶段**：首次价值交付，获得贡献点
- **奔涌阶段**：持续成长，建立影响力

#### 1.1.2 10倍好体验量化指标

所谓的"10倍好"，在技术实现层面被具体量化为：

1. **极简运维**：完全依赖 PostgreSQL 16 的强大扩展能力（Unlogged Tables 做缓存、SKIP LOCKED 做队列、pgvector 做向量检索、JSONB 做文档存储、TSVector 做全文检索）。系统维护节点减少至原来的 1/5。
2. **AI 辅助编码友好**：源代码结构采用严格的 **Service Action** 模式与 **Data Transfer Object (DTO)** 模式。高度解耦、强类型的代码风格，便于 GitHub Copilot、Cursor 等 AI 编程助手精准理解上下文。
3. **双端融合**：管理端采用 **Filament v3**（基于 Livewire）构建全功能后台；小程序端采用 **uni-app + Vue 3**，在保持跨端体验的同时，复用 Laravel 的路由与控制器逻辑。
4. **智能化运营**：集成腾讯云/阿里云AI服务，支持音视频转写、RAG知识库、智能问答，实现会议内容自动转化为公司资产。

### 1.4 技术架构详细规范

#### 1.4.1 技术栈选型

- **后端框架**：Laravel 11 (PHP 8.3)。利用其最新的精简骨架与强类型支持。
- **数据库**：PostgreSQL 16。
  - 扩展：`pgvector` (向量存储), `pg_trgm` (模糊匹配), `zhparser` (中文分词)。
  - 优化：Session 和 Cache 表配置为 `UNLOGGED` 表，牺牲崩溃后的持久性以换取接近 Redis 的读写性能。
- **前端技术**：
  - **管理端**：Filament v3 + TailwindCSS + Alpine.js (TALL Stack)。
  - **小程序端**：uni-app + Vue 3 + uView Pro + TypeScript。
- **AI服务**：混合AI模型路由
  - **主力模型**：DeepSeek V3/R1 (性价比优先)
  - **高端能力**：OpenAI GPT-4o (多模态处理)
  - **合规兜底**：阿里通义千问 (中文处理)
- **容器化**：Docker Compose 单机编排，包含 `app` (PHP-FPM), `db` (PostgreSQL), `nginx` 三个核心容器。

#### 1.4.2 源码目录结构规范 (AI-Native)

为了确保 AI 能够准确生成代码，项目强制执行以下目录结构与命名规范：

- **`app/Actions/` (业务原子层)**：
  - 禁止在 Controller 中编写业务逻辑。所有业务操作必须封装为 Action 类。
  - **规范**：类名必须以动词开头（如 `CreateUserAction`），仅包含唯一的 `handle()` 公有方法。
  - **目的**：单一职责原则（SRP），便于 AI 理解输入输出，易于单元测试。
- **`app/Data/` (数据契约层)**：
  - 禁止使用关联数组传递业务数据。必须使用 `spatie/laravel-data` 定义 DTO。
  - **规范**：属性强类型，支持 Validation 属性注解。
  - **目的**：提供IDE自动补全，强制数据结构契约，减少运行时错误。
- **`app/Services/` (外部集成层)**：
  - 封装第三方 API（如腾讯云 ASR、OpenAI）或复杂的解析逻辑。
  - **示例**：`app/Services/WeCom/Parsers/HtmlLogParser.php`。
- **`database/migrations/` (架构演进层)**：
  - 包含标准迁移文件及 SQL 宏定义。特别注意 PostgreSQL 特有功能的开启（如 `CREATE EXTENSION vector`）。

// 基于角色的权限控制
class UserPolicy
{
    public function viewAny(User $user): bool
    {
        return $user->hasRole(['admin', 'manager']);
    }

    public function create(User $user): bool
    {
        return $user->hasRole('admin');
    }

    public function update(User $user, User $model): bool
    {
        return $user->hasRole('admin') ||
               ($user->hasRole('manager') && $user->department_id === $model->department_id);
    }

    public function syncXiaoe(User $user, User $model): bool
    {
        return $user->hasRole(['admin', 'manager']) ||
               ($user->hasRole('operator') && $user->department_id === $model->department_id);
    }
}

## 6. 安全设计

### 6.1 认证安全

- **JWT Token**: API认证使用JWT，支持多端登录
- **微信授权**: 小程序使用微信授权登录，基于UnionID防绕过
- **密码安全**: Argon2id哈希，密码复杂度要求
- **Session管理**: Redis存储会话，支持单点登录
- **MFA支持**: 预留手机号验证码二次认证接口

### 6.2 数据安全

- **数据加密**: 敏感数据加密存储
- **传输加密**: HTTPS强制，所有API必须HTTPS
- **SQL注入防护**: 使用Eloquent ORM参数绑定
- **XSS防护**: 前端数据转义，后端内容过滤
- **CSRF防护**: Laravel Sanctum CSRF Token机制

### 6.3 API安全

- **请求频率限制**: 基于Redis的Rate Limiting
- **API密钥管理**: 不同客户端使用不同API Key
- **请求签名**: 重要API要求请求签名验证
- **敏感操作审计**: 关键操作记录操作日志

### 6.4 权限控制

- **RBAC模型**: 基于角色的访问控制
- **数据级权限**: 行级安全（Row Level Security）
- **API权限**: 细粒度的API权限控制
- **功能开关**: 基于角色的功能可见性控制
- **审计日志**: 所有重要操作记录
