## 1. 项目全景与架构愿景

### 1.1 核心设计哲学：宏大单体与AI原生

本项目的架构蓝图建立在“宏大单体（Majestic Monolith）”与“AI原生（AI-Native）”的双重基石之上。在当前微服务架构盛行的背景下，我们反其道而行，旨在通过极简的架构降低系统的熵值，从而实现“10倍好（10x Better）”的交付效率与运维体验。

所谓的“10倍好”，在技术实现层面被具体量化为：

1. **极简运维**：摒弃 Redis、Elasticsearch、RabbitMQ 等外部中间件，完全依赖 PostgreSQL 16 的强大扩展能力（Unlogged Tables 做缓存、SKIP LOCKED 做队列、pgvector 做向量检索、JSONB 做文档存储）。这种 All-in-One 的策略将系统维护节点减少至原来的 1/5。
2. **AI 辅助编码友好**：源代码结构采用严格的 **Service Action** 模式与 **Data Transfer Object (DTO)** 模式。这种高度解耦、强类型的代码风格不仅利于人类阅读，更是为了让 GitHub Copilot、Cursor 等 AI 编程助手能够精准地理解上下文，从而生成高质量的业务逻辑代码。
3. **双端融合**：前端采用 **Filament v3**（基于 Livewire）构建全功能管理后台，利用其声明式 UI 快速迭代；用户端采用 **Inertia.js + Vue 3**，在保持单页应用（SPA）流畅体验的同时，复用 Laravel 的路由与控制器逻辑，避免了传统前后端分离带来的 API 维护成本 1。

### 1.2 业务模块规划全景

系统主要划分为四大核心业务域，通过 OneID 串联，形成数据资产的闭环流动：

| **模块域**                          | **核心职责**                                          | **关键技术特征**                                             |
| ----------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------ |
| **OneID (核心底座)**                | 统一身份认证、RBAC 权限控制、组织架构管理、审计日志。 | UUID v7 主键、三层角色体系、动态权限 Gate 1。                |
| **智能网盘 (Intelligent Drive)**    | 企业非结构化数据存储、分片上传、细粒度分享控制。      | Flysystem 抽象存储、SHA-256 秒传、PostgreSQL 全文检索 1。    |
| **AI 工场 (Knowledge Engine)**      | 音视频 ASR 转写、文本清洗、RAG 向量化、知识问答。     | 腾讯/阿里 ASR 接口、pgvector 向量库、HNSW 索引、语义切片 1。 |
| **活动与归档 (Activity & Archive)** | 企微聊天记录非侵入式归档、活动发布与高并发报名。      | DomCrawler 解析引擎、乐观锁（Optimistic Locking）并发控制 3。 |



### 1.3 技术架构详细规范

#### 1.3.1 技术栈选型

- **后端框架**：Laravel 11 (PHP 8.3)。利用其最新的精简骨架（Slim Skeleton）与强类型支持。
- **数据库**：PostgreSQL 16。
  - 扩展：`pgvector` (向量存储), `pg_trgm` (模糊匹配), `zhparser` (中文分词)。
  - 优化：Session 和 Cache 表配置为 `UNLOGGED` 表，牺牲崩溃后的持久性以换取接近 Redis 的读写性能 1。
- **前端技术**：
  - **Admin**：Filament v3 + TailwindCSS + Alpine.js (TALL Stack)。
  - **Portal**：Inertia.js + Vue 3 + TailwindCSS。
- **容器化**：Docker Compose 单机编排，包含 `app` (PHP-FPM), `db` (PostgreSQL), `nginx` 三个核心容器 1。

#### 1.3.2 源码目录结构规范 (AI-Native)

为了确保 AI 能够准确生成代码，项目强制执行以下目录结构与命名规范：

- **`app/Actions/` (业务原子层)**：
  - 禁止在 Controller 中编写业务逻辑。所有业务操作必须封装为 Action 类。
  - **规范**：类名必须以动词开头（如 `CreateUserAction`），仅包含唯一的 `handle()` 公有方法。
  - **目的**：单一职责原则（SRP），便于 AI 理解输入输出，易于单元测试。
- **`app/Data/` (数据契约层)**：
  - 禁止使用关联数组（Associative Arrays）传递业务数据。必须使用 `spatie/laravel-data` 定义 DTO。
  - **规范**：属性强类型，支持 Validation 属性注解。
  - **目的**：提供IDE自动补全，强制数据结构契约，减少运行时错误 4。
- **`app/Services/` (外部集成层)**：
  - 封装第三方 API（如腾讯云 ASR、OpenAI）或复杂的解析逻辑。
  - **示例**：`app/Services/WeCom/Parsers/HtmlLogParser.php` 1。
- **`database/migrations/` (架构演进层)**：
  - 包含标准迁移文件及 SQL 宏定义。特别注意 PostgreSQL 特有功能的开启（如 `CREATE EXTENSION vector`）6。

## 2. 数据库详细设计与宏定义

数据库设计是“宏大单体”稳定性的基石。为了应对未来可能的字段扩展并保持审计追踪能力，我们利用 Laravel 的 `Blueprint` Macro 功能定义了一套标准化的建表规范。所有业务表（除中间表外）必须遵循此规范。

### 2.1 标准宏 (Blueprint Macros) 定义

我们将通过 `AppServiceProvider` 注入以下宏，以实现“一次定义，处处复用”。

#### 2.1.1 核心宏逻辑代码

PHP

```
// app/Providers/AppServiceProvider.php

use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

public function boot(): void
{
    // 1. 标准主键：UUID v7
    // 理由：UUID v7 结合了随机性与时间有序性，解决了 UUID v4 导致的数据库索引页分裂问题，性能接近自增 ID.[7, 8]
    Blueprint::macro('standardKey', function () {
        $this->uuid('id')->primary()->comment('UUID v7 Primary Key');
    });

    // 2. 审计字段：创建者与更新者
    // 理由：记录数据变更的责任人，nullable 是为了兼容系统自动执行的任务（无用户上下文）.[9, 10]
    Blueprint::macro('auditColumns', function () {
        $this->foreignId('created_by')
             ->nullable()
             ->constrained('users')
             ->nullOnDelete()
             ->comment('创建者ID');
        
        $this->foreignId('updated_by')
             ->nullable()
             ->constrained('users')
             ->nullOnDelete()
             ->comment('最后更新者ID');
             
        $this->timestamps(); // 包含 created_at, updated_at
    });

    // 3. 软删除（带操作人）
    // 理由：标准的 softDeletes 只记录时间，无法追溯是谁删除了数据。扩展此宏以增强审计能力.[11]
    Blueprint::macro('softDeletesWithActor', function () {
        $this->softDeletes(); // deleted_at
        $this->foreignId('deleted_by')
             ->nullable()
             ->constrained('users')
             ->nullOnDelete()
             ->comment('删除人ID');
    });

    // 4. 通用扩展字段
    // 理由：在单体架构中，为了减少频繁变更 Schema 带来的迁移成本，预留通用字段用于存储非核心业务数据.
    // text1-3 用于短文本检索，json_data 利用 Postgres 的 JSONB 特性存储结构化扩展数据。
    Blueprint::macro('extensionFields', function () {
        $this->string('text1')->nullable()->comment('扩展字段1 (索引)');
        $this->string('text2')->nullable()->comment('扩展字段2');
        $this->string('text3')->nullable()->comment('扩展字段3');
        $this->jsonb('json_data')->nullable()->comment('JSONB 扩展数据');
        
        // 为 text1 建立索引以备检索
        $this->index('text1'); 
    });
    
    // 5. 全能建表宏（组合上述所有）
    Blueprint::macro('universalTable', function () {
        $this->standardKey();
        $this->auditColumns();
        $this->softDeletesWithActor();
        $this->extensionFields();
    });
}
```

Service Action: UploadFileAction

包含秒传逻辑和 AI 任务触发。

PHP

```
namespace App\Actions\Drive;

use App\Models\File;
use App\Data\Drive\UploadFileDto;
use Illuminate\Support\Facades\Storage;
use App\Jobs\ProcessAiTasksJob;

class UploadFileAction
{
    public function handle(UploadFileDto $dto): File
    {
        $uploadedFile = $dto->file;
        
        // 1. 计算文件哈希 (SHA-256) 实现秒传
        $hash = hash_file('sha256', $uploadedFile->path());
        
        // 2. 检查是否已存在相同 Hash 的文件 (全局去重)
        $existingFile = File::where('hash', $hash)->first();
        if ($existingFile) {
            // 仅创建新的元数据记录，复用物理路径
            return $this->createFileRecord($dto, $existingFile->path, $hash);
        }

        // 3. 物理存储：路径按 UserID/日期 分隔，避免单目录文件过多
        $path = $uploadedFile->storeAs(
            "private/files/{$dto->user_id}/". date('Ymd'), 
            $hash. '.'. $uploadedFile->extension()
        );

        // 4. 创建数据库记录
        $file = $this->createFileRecord($dto, $path, $hash);

        // 5. 如果是音视频，触发 AI 处理任务队列
        if (str_starts_with($file->mime_type, 'audio/') |

| str_starts_with($file->mime_type, 'video/')) {
            ProcessAiTasksJob::dispatch($file);
        }

        return $file;
    }

    private function createFileRecord(UploadFileDto $dto, string $path, string $hash): File
    {
        return File::create();
    }
}
```

#### 3.3.2 逻辑层设计

核心逻辑：异步任务链

AI 处理流程通常耗时较长，通过 Laravel Job 链式调用处理。

1. **`ProcessMediaJob`**: 负责将文件发送给 ASR 服务商。

**Action: `VectorizeContentAction` (伪代码)**

PHP

```
class VectorizeContentAction
{
    public function handle(string $text, int $fileId): void
    {
        // 1. 语义切片 (Semantic Chunking)
        // 使用正则或简单的换行符将长文本切分为 500-1000 token 的段落
        $chunks = $this->chunkText($text, 1000);

        foreach ($chunks as $chunk) {
            // 2. 调用 OpenAI/DashScope 接口获取 Embedding
            $vector = OpenAI::embeddings()->create([
                'model' => 'text-embedding-ada-002',
                'input' => $chunk,
            ])->embedding;

            // 3. 存入 pgvector 表
            // 注意：需将数组转换为 Postgres 向量格式字符串 '[0.1, 0.2,...]'
            DB::table('ai_vectors')->insert([
                'file_id' => $fileId,
                'content_chunk' => $chunk,
                'embedding' => '['. implode(',', $vector). ']',
                'created_at' => now(),
            ]);
        }
    }
}
```

Service Action: JoinEventAction

使用数据库字段 version 实现乐观锁，防止超卖。

PHP

```
class JoinEventAction
{
    public function handle(JoinEventDto $dto): void
    {
        $user = User::find($dto->user_id);
        
        // 1. 循环重试机制 (Spin Lock)
        $attempts = 0;
        do {
            $event = Event::find($dto->event_id);
            
            // 2. 基础容量检查
            if ($event->registered_count >= $event->max_participants) {
                throw new DomainException('活动已满员');
            }
            
            // 3. 乐观锁更新
            // update events set registered_count = count+1, version = version+1 
            // where id =? and version =? and registered_count < max
            $updated = Event::where('id', $event->id)
                ->where('version', $event->version) // 关键：检查版本号是否被其他事务修改
                ->where('registered_count', '<', $event->max_participants) // 双重保险
                ->update();
                
            if ($updated) {
                // 4. 更新成功，写入报名记录表
                EventRegistration::create();
                return;
            }
            
            $attempts++;
            usleep(100000); // 暂停 100ms 后重试
            
        } while ($attempts < 3); // 最多重试 3 次

        throw new DomainException('报名人数过多，请稍后重试');
    }
}
```

### 4.4 Gitee Go 流水线配置 (PHP Laravel)

根据 Gitee Go 的 YAML 语法规范 16，以下是用于 PHP Laravel 项目的 CI/CD 配置示例。文件路径：`/.workflow/pipeline.yml`。

name: Production Pipeline
