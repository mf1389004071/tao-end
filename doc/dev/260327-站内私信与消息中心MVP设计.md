# 站内私信与消息中心 MVP 设计（bt10）

## 1. 目标与范围（MVP）

### 1.1 用户可感知目标

- **活动详情页**点击「咨询」后，进入与“活动负责人”的私信对话，可输入并发送文本消息。
- 发送方发送后，**接收方在消息中心可看到新私信**（列表+进入对话）。
- 同时保留现有的「系统通知/公告」入口，形成一个“消息中心”。

### 1.2 不在 MVP 范围（后续迭代）

- 语音/图片/文件消息
- 群聊
- 复杂风控（敏感词、拉黑、举报）与内容审核全链路
- 强一致已读回执、消息撤回

---

## 2. 现有表与可复用能力（来自 Liquibase）

以 `tao-end/geek-admin/src/main/resources/db/changelog/changelog-2-business.xml` 为准，已存在：

- `notifications`：站内通知（当前前端已在 `tao-app/src/pages/cust/msg.vue` 使用）
- `notices`：公告（同上）
- `user_activity_logs`：用户行为日志，可用于记录 “SEND_MESSAGE/READ_MESSAGE” 等行为（可选）

说明：**通知/公告 ≠ 私信**。通知通常是系统生成、单向；私信需要会话与双向消息记录，因此建议新增独立表。

---

## 3. 数据模型设计（建议新增表）

### 3.1 私信会话表：`message_thread`

一条记录代表“两个用户之间的一条私信会话”（MVP 先做 1v1）。

字段建议：

- `id` BIGINT：主键
- `user_a_id` BIGINT：参与者 A（较小 userId 可固定放 A，便于唯一约束）
- `user_b_id` BIGINT：参与者 B
- `last_message_id` BIGINT：最后一条消息 id（便于列表展示）
- `last_message_time` TIMESTAMPTZ：最后一条消息时间（排序）
- `last_message_preview` TEXT：最后消息预览（列表用）
- `a_unread_count` INT：A 未读数
- `b_unread_count` INT：B 未读数
- 审计字段：`create_id/create_time/update_id/update_time/status/del_flag/remark`（沿用项目风格）

关键约束：

- 唯一约束：`(user_a_id, user_b_id)` 唯一（确保 1v1 只有一个 thread）

### 3.2 私信消息表：`message`

字段建议：

- `id` BIGINT：主键
- `thread_id` BIGINT：所属会话
- `sender_id` BIGINT：发送者
- `receiver_id` BIGINT：接收者
- `message_type` VARCHAR(20)：`TEXT`（MVP）
- `content` TEXT：正文
- `sent_time` TIMESTAMPTZ：发送时间
- `read_time` TIMESTAMPTZ：已读时间（可空）
- 审计字段同上

索引建议：

- `idx_message_thread_time(thread_id, sent_time desc)`
- `idx_message_receiver_unread(receiver_id, read_time)`

## 4. 与活动“负责人”的关系（咨询入口如何拿到接收者）

### 4.1 约定：活动负责人 userId 来源

为了让“咨询”能准确找到接收者，需要后端 `event_info` 或详情接口返回负责人字段（建议其一）：

- `owner_user_id`（或 `pm_user_id/manager_id` 等项目惯用字段命名）
- 或者在 `event_info` 里已有字段（需以现有表为准，不新增则在接口 DTO 里补齐）

MVP 推荐：**活动详情接口返回 `ownerUserId`（字符串化）与 `ownerUserName`**，前端无需额外查用户表。

## 5. API 设计（建议新增 bt10 私信接口）

### 5.1 创建/获取会话

- `POST /bt10/messageThread/ensure`
  - 入参：`targetUserId`（对方用户 id，字符串）
  - 出参：`threadId`
  - 逻辑：按 `(min(me,target), max(me,target))` 查 thread；不存在则创建。

### 5.2 会话列表（消息中心“私信”tab）

- `GET /bt10/messageThread/list`
  - 入参：分页
  - 出参：`rows/total`，包含：`threadId`、`targetUserId`、`targetUserName`、`lastMessagePreview`、`lastMessageTime`、`unreadCount`

### 5.3 拉取会话消息

- `GET /bt10/message/list`
  - 入参：`threadId`、分页（按时间倒序/正序约定）
  - 出参：消息列表（`id/senderId/content/sentTime/readTime`）

### 5.4 发送消息

- `POST /bt10/message/send`
  - 入参：`threadId`、`content`
  - 逻辑：写入 message；更新 thread 的 last_* 字段；对接收方 unread +1

### 5.5 标记已读

- `POST /bt10/message/read`
  - 入参：`threadId`（或 messageIds）
  - 逻辑：把 receiver=me 的消息 read_time 补齐；清零我方 unread_count

## 6. 前端交互建议（tao-app）

### 6.1 消息中心信息架构

- Tab1：系统通知（公告/notifications）
- Tab2：互动通知（点赞/评论/收藏/分享等，后续对齐 `user_activity_logs` 与聚合计数）
- Tab3：私信（message_thread 列表）

### 6.2 咨询入口

- 活动详情页「咨询」：调用 `ensure` 获取 threadId → 跳转到 `dm-chat` 页面（新建）并带 threadId。

---

## 7. 安全与合规（最小要求）

- 只允许会话参与者读写自己的 thread/message
- 发送频控（同一 sender 每分钟上限）可后置，但建议预留
- 内容长度限制（例如 1000 字）与基础 XSS/注入防护（服务端）
