# PC 端微信扫码登录 & App 端微信快捷登录——完整性分析与启用配置

更新时间：2026-03-27  
范围：`tao-pc`（管理端）微信扫码登录、`tao-app`（小程序端）微信快捷登录、`tao-end`（后端）微信 OAuth 承接

## 1. 结论（高优先级）

- **App 端（小程序）微信快捷登录：链路“基本完整”，但必须配置后端 `oauth.wx.miniapp.*` 为真实值才能用。**
  - 前端已实现 `wx.login()` 拿 code → 调后端换 token → 保存 token → 拉取用户信息 → 跳首页。
  - 后端有 `POST /oauth/wx/login/miniapp/{code}`，默认支持 **自动注册**（未绑定时创建系统用户 + 绑定 openid）。
- **PC 端微信扫码登录：目前“功能不完整/默认不可用”。**
  - 前端打开第三方登录链接时 **取错返回字段**：打开了 `response.msg`（实际是“操作成功”），而正确应为 `response.data`（授权跳转 URL）。
  - 前端传的 provider 为 `wechat`，但后端 JustAuth 微信来源实际支持的是 **`wechat_open`（开放平台）** 或 **`wechat_mp`（公众号）**，因此即使配置了微信来源，也会因为 source 不匹配而提示“不支持”。

- **当前项目实际同时存在两套方案：**
  - **PC 端（管理后台 Web）**：走 **JustAuth**（`GET /system/auth/login/{source}` → 回调 `GET /system/auth/social-login/{source}`），更适合“网页扫码/网页授权”场景。
  - **App 端（小程序）**：走 **自研微信登录（code2session 交换 token）**（`POST /oauth/wx/login/miniapp/{code}`），更适合“小程序一键登录”场景。

- **就“PC 端微信扫码登录”而言：项目自带支持、且最容易落地的是 JustAuth 路线。**
  - 原因：后端已经有 `SysAuthController` 全链路（生成授权 URL + 处理回调 + 产出系统 token），前端只需做“字段修复 + source 对齐”，并补齐 `application-auth.yml` 的 `justauth.sources.wechat_open/wechat_mp` 配置即可。
  - 反之：如果强行用自研 `/oauth/wx/login/pub/{code}` 来做 PC/H5 微信授权，当前实现与公众号 OAuth2 返回结构不匹配，需要重做参数与字段解析（见第 4.2 节），整体改动更大。

> 额外说明：后端还存在一个 `pub` 登录通道（`/oauth/wx/login/pub/{code}`），但当前实现按小程序参数拼接请求，且强依赖 `session_key` 字段，**与公众号网页 OAuth2 返回结构不匹配**，因此该通道实际不可用（详见第 4 节）。

## 2. 现状链路梳理

### 2.1 PC 端（`tao-pc`）第三方登录入口（含微信按钮）

- 入口页面：`tao-pc/src/views/auth/oauth.vue`
- 行为：点击“微信”按钮会调用：
  - `GET /system/auth/login/{provider}`
  - 成功后 `window.open(...)` 打开后端返回的授权地址

后端对应：

- `tao-end/geek-scenes/Geek-Scene-Auth/geek-oauth-justauth/.../SysAuthController.java`
  - `GET /system/auth/login/{source}`：返回 `AjaxResult.success(authorizeUrl)`，即授权 URL 在 **`data` 字段**。
  - 微信来源在 JustAuth 工具中是 `wechat_open`/`wechat_mp`（不是 `wechat`）。

**因此 PC 端当前至少有两处“硬不通”：**

1) **打开 URL 取错字段**：应该打开 `data`，不是 `msg`。  
2) **source 不匹配**：PC 传 `wechat`，后端支持的是 `wechat_open`/`wechat_mp`，且 `application-auth.yml` 默认也没配置微信来源。

### 2.2 App 端（`tao-app`）小程序微信快捷登录

- 入口页面：`tao-app/src/pages_mine/pages/login/index.vue`
- 仅在小程序端启用：`// #if MP-WEIXIN` 时显示按钮“微信一键登录”
- 行为：
  - `getWxCode()` 内部 `wx.login()` → `code`
  - 调 `wxLogin('miniapp', code)` → `POST /oauth/wx/login/miniapp/{code}`
  - 成功后读取 `res.token` → `setToken(res.token)` → `userStore.getInfo()` → `uni.switchTab('/pages/cust/home')`

后端对应：

- `tao-end/geek-scenes/Geek-Scene-Auth/geek-oauth-wx/.../WxLoginController.java`
  - `POST /oauth/wx/login/{source}/{code}`：当 `source=miniapp` 调 `WxMiniAppLoginServiceImpl.doLogin(code, true)` 并返回 `token` 字段
- 配置读取：
  - `oauth.wx.miniapp.appId/appSecret/url`（见 `WxMiniAppConstant`）
  - 默认 `url` 指向 `https://api.weixin.qq.com/sns/jscode2session`（见 `application-auth.yml`）

## 3. 启用/调整配置怎么做（可执行清单）

### 3.1 后端：启用小程序微信快捷登录（必须）

文件：`tao-end/geek-admin/src/main/resources/application-auth.yml`

把以下配置替换为真实值：

- `oauth.wx.miniapp.appId`: 你的微信小程序 AppID
- `oauth.wx.miniapp.appSecret`: 你的微信小程序 AppSecret
- `oauth.wx.miniapp.url`: 保持默认即可（一般不需要改）

也可按需补齐公众号配置（若未来要用 `pub` 或公众号网页授权）：

- `oauth.wx.pub.appId`
- `oauth.wx.pub.appSecret`
- `oauth.wx.pub.url`

注意：

- `application.yml` 中 `spring.profiles.active` 已包含 `auth`，因此 `application-auth.yml` 会被加载（无需额外“开关”）。

### 3.2 App 端：确认小程序 AppID（必须）

文件：`tao-app/src/manifest.json`

- `mp-weixin.appid` 已存在（当前为 `wx49bc42162a3f2409`）。
- 若你要对接自己的小程序，请替换为你的小程序 AppID，并在微信开发者工具中使用对应项目设置。

### 3.3 后端：启用 PC 端“微信扫码登录”（需要额外配置 + 小修复）

#### (A) 配置 JustAuth 的微信来源（后端配置）

文件：`tao-end/geek-admin/src/main/resources/application-auth.yml`

在 `justauth.sources` 下新增 **二选一**（按你的微信资质选择）：

- **优先：网站应用/开放平台扫码登录**：使用 `wechat_open`
- **降级：公众号（网页授权）**：使用 `wechat_mp`

需要提供：

- `clientId`：对应平台的 AppID
- `clientSecret`：对应平台的 AppSecret
- `redirectUri`：回调地址（后端接口），形如：`https://你的域名/system/auth/social-login/wechat_open`

> 你当前文件里只配置了 `gitee/github`，所以 `wechat_*` 目前默认必定“不支持”。

建议配置策略（符合“有开放平台优先，否则降级公众号”）：

- 先在 `application-auth.yml` 配置并启用 `justauth.sources.wechat_open`
- 若你没有开放平台能力/资质，再配置并启用 `justauth.sources.wechat_mp`
- **前端按钮的 source 与后端保持一致**（二选一），不要同时写 `wechat_open` 和 `wechat_mp`，避免用户点击后进入非预期渠道

#### (B) PC 端必须做的最小修复（否则仍然不可用）

文件：`tao-pc/src/views/auth/oauth.vue`

需要改两点（概念层面，不在本文直接改代码）：

1) **取回调字段**：`GET /system/auth/login/{source}` 成功返回的授权 URL 在 `data`，不是 `msg`  
2) **source 名称**：把按钮传参从 `wechat` 改为 `wechat_open` 或 `wechat_mp`（与后端配置保持一致）

## 4. 完整性缺口与风险点（按严重度）

### 4.1 P0：PC 端微信扫码登录当前必定不可用

- 前端打开了 `response.msg`（“操作成功”），不会打开授权地址
- 前端传 `wechat`，后端 JustAuth 实际是 `wechat_open`/`wechat_mp`；并且后端默认未配置微信来源

**影响**：即使你把微信来源配置好了，PC 端按钮仍然会失败或打开错误页面。

### 4.2 P0：后端 `pub` 登录通道实现与公众号 OAuth2 不匹配

相关代码：

- `WxLoginController`: `POST /oauth/wx/login/pub/{code}`
- `WxPubLoginServiceImpl` + `WxLoginService.doAuth(...)`

问题点：

- `doAuth(...)` 固定拼接参数 `js_code=`（小程序专用），公众号网页 OAuth2 应为 `code=`；请求 URL 也不同（`sns/oauth2/access_token`）
- `doAuth(...)` 强依赖返回 `session_key`，但公众号 OAuth2 返回通常没有 `session_key` 字段

**影响**：若你计划用公众号网页授权（H5 内微信浏览器），需要重做/调整 `pub` 链路（至少要分支处理参数与返回字段）。

> 这里的“OAuth2”指的是公众号网页授权那套 OAuth2 协议流程；当前仓库里用于 PC/H5 的“第三方网页登录”更偏向 **JustAuth 的统一封装**，不是 Spring Security OAuth2 Client 那套。

### 4.3 P1：小程序登录“自动注册”策略的产品/安全考量

当前 `WxMiniAppLoginServiceImpl.doLogin(code, true)` 会在未绑定时自动创建用户：

- `userName/nickName` 直接使用 `openid`
- `password` 使用 `code` 加密后保存

**影响**：

- 账号体系会出现大量“openid 用户名”的自动账户
- 若你希望“必须先绑定已有账号/手机号”再登录，这里需要产品策略调整（本文只做现状分析）

## 5. 推荐的验证步骤（从零到跑通）

### 5.1 验证 App 端小程序微信快捷登录

1) 在 `tao-end` 配置好 `oauth.wx.miniapp.appId/appSecret`
2) 启动后端（确保 `auth` profile 生效）
3) 用微信开发者工具运行 `tao-app` 小程序端
4) 进入登录页点击“微信一键登录”
5) 后端应返回 `{"code":200, "token":"..."}`（或同等结构），小程序本地应保存 token 并跳转首页

### 5.2 验证 PC 端微信扫码登录（在修复 + 配置后）

1) 在后端 `application-auth.yml` 配置 `justauth.sources.wechat_open`（或 `wechat_mp`）
2) 修复 `tao-pc` 的 `oauth.vue`：改用 `response.data`，并把 source 改为 `wechat_open`/`wechat_mp`
3) 启动 `tao-pc`，点击“微信”按钮应打开微信授权页
4) 扫码/授权后回调到 `GET /system/auth/social-login/{source}` 并返回系统 token

## 7. 到底用 JustAuth 还是 OAuth2？项目自带支持哪个？哪个更容易？

### 7.1 项目自带的两类“微信相关登录”能力

- **JustAuth（第三方登录聚合框架）**
  - 代码模块：`tao-end/geek-scenes/Geek-Scene-Auth/geek-oauth-justauth`
  - 依赖：`me.zhyd.oauth:JustAuth`（在 `geek-oauth-justauth/pom.xml` 中声明）
  - 适用：PC Web 的扫码/网页登录授权（尤其是“开放平台网站应用扫码”= `wechat_open`）
  - 配置入口：`application-auth.yml` 的 `justauth.sources.*`

- **自研微信登录（小程序 code2session / 公众号换 token 的 HTTP 调用）**
  - 代码模块：`tao-end/geek-scenes/Geek-Scene-Auth/geek-oauth-wx`
  - 适用：小程序 `wx.login()` → `code2session` 这种“快捷登录”（当前已打通 `miniapp`）
  - 配置入口：`application-auth.yml` 的 `oauth.wx.*`

### 7.2 结论（落地难度与推荐）

- **App 端（小程序快捷登录）**：用自研 `/oauth/wx/login/miniapp/{code}` 最顺（现成链路 + 现成配置项）。
- **PC 端（扫码登录）**：用 JustAuth 最顺（现成全链路 Controller + 微信 source 已在工具类列出），只差“配置 + 前端最小修复”。
- **不推荐** 现在用自研 `/oauth/wx/login/pub/{code}` 去承接 PC/H5 的公众号 OAuth2：因为实现不匹配，修起来比 JustAuth 落地成本高。
