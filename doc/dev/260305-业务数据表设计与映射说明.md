# 260305 业务数据表设计与映射说明

> 版本：v1.0  
> 范围：`changelog-1-master.xml` + `changelog-2-business.xml` 相关业务表  
> 目标：说明业务能力与数据模型的对应关系，指导后续接口与前后端实现。

## 1. 用户与画像域

- **核心业务能力**
  - OneID 统一身份：所有成员必须有账号，以账号参与系统内业务。
  - 人物画像：基础信息 + 丰富标签（能力/兴趣/行业/资源/需求等）+ 心树/心钥/商业定位成果。

- **表与字段组合**
  - **业务用户 = `sys_user` + `user_profiles`**（OneID 统一身份，不单独建 users 表）：
    - `sys_user`（changelog-1）：RuoYi 框架侧用户、登录账号与权限主体；**同用途字段仅保留在本表**，避免与业务扩展重复。
      - 账号与基础：`user_name, nick_name, phonenumber, email, avatar, password, status, dept_id`
      - 登录与审计：`login_ip, login_date, pwd_update_date, create_by, update_by, create_time, update_time`
    - `user_profiles`（business-039 + business-039b）：与 `sys_user` 一对一，补充业务扩展（原 business-003 users 表能力已合并入此表）。
      - 积分与贡献点：`points, total_points, contribution_points, total_contribution_points`
      - 成长与活跃：`growth_stage, join_date, last_active_at`
      - 第三方标识：`wechat_unionid, wechat_openid, miniapp_openid, work_userid, xiaoe_user_id, xiaoe_data`
      - 邀请：`inviter_id, invitation_code`；业务角色：`biz_role`
      - 商业定位与画像：`heart_tree_url, heart_key_url, business_positioning`，`best_photo_url, avatar_wechat_url, avatar_promo_url, promo_image_url`，`talent_summary`，`available_time_slots, appointment_status`
      - 扩展：`extra_profile(jsonb)`、`text1/text2/text3`、`json_data`
  - `tags` + `user_tags`（business-040/041）
    - `tags`：通用标签池（能力/兴趣/行业/资源/需求/价值观/成就等），可树形组织。
    - `user_tags`：用户与标签的多对多关联，支持权重与来源，用于画像与推荐（相当于“人物特征向量”）。

## 2. 积分与贡献点域

- **核心业务能力**
  - 双币种体系：贡献点（1:1 人民币）+ 积分（行为奖励，1 年过期）。
  - 审计与统计：流水 + 变更日志。

- **表与字段组合**
  - 余额：`user_profiles.points` / `user_profiles.contribution_points` 及其累计字段。
  - 流水：
    - `user_point_logs`（business-004）：积分收支流水，记录“获得/消耗”场景。
    - `user_contribution_logs`（business-005）：贡献点收支流水（充值/购买/退款/奖励）。
  - 变更审计：
    - `point_change_logs`（business-032）：按“变更事件”维度记录积分变动（获得/消耗/过期/调整），前后余额与关联业务。

## 3. 邀请与成长域

- **核心业务能力**
  - 邀请有礼：邀请码 + 邀请关系 + 奖励（积分/贡献点）。
  - 成长阶段：从“粉丝”到“高手/合伙人”等的成长路线。

- **表与字段组合**
  - `user_invitations`（business-006）：被邀请人、邀请人、邀请码、奖励发放状态。
  - `user_growth_records`（business-007）：用户成长阶段变更历史，记录 from/to 与触发方式。

## 4. 知识库域（工具库/话题/金句等）

- **核心业务能力**
  - 结构化知识沉淀：分类 + 内容 + 统计。
  - 社交互动：评论、点赞、收藏。

- **表与字段组合**
  - 分类：`knowledge_categories`（business-008）
    - 支持树形结构与权限等级。
  - 内容：`knowledge_contents`（business-009）
    - 标题/正文/类型 + 作者/负责人/贡献人 + 统计字段 + SEO + AI 摘要。
  - 互动：
    - 评论：`knowledge_comments`（business-010）
    - 点赞：`knowledge_likes`（business-011）
    - 收藏：`knowledge_collections`（business-012）

## 5. 活动与线下课程域

- **核心业务能力**
  - 标准办课流程：活动主信息 + 角色分工 + 报名 + 场次 + 签到。
  - 支持周期活动、转化跟进、积分奖励。

- **表与字段组合**
  - 主体：`events`（business-013）
    - 时间/地点/容量/状态 + 课程信息（价格/类型/目标学员/学习目标/课程结构与大纲）。
  - 角色：`event_roles`（business-014）
    - 角色名 + 权责描述 + 人数限制 + 奖励（积分/贡献点）。
  - 报名与角色分配：
    - 报名：`event_registrations`（business-015）
    - 角色分配：`event_registration_roles`（business-016）
  - 场次与签到：
    - 场次：`event_sessions`（business-017）
    - 签到：`event_check_ins`（business-018）
  - 活动变更审计：
    - `event_change_logs`（business-031）

## 6. AI 知识工厂与向量库

- **核心业务能力**
  - AI 任务调度：转写/摘要/向量化/对话。
  - 会议内容资产化：转写 + 关键点 + 行动项。
  - RAG 检索：向量知识库 + HNSW 索引。

- **表与字段组合**
  - AI 任务：`ai_tasks`（business-019）
  - 会议转写：`meeting_transcripts`（business-020）
  - 向量库：`ai_vectors`（business-036/037/038）

## 7. 小鹅通集成与文件管理

- **核心业务能力**
  - 小鹅通订单、用户同步。
  - 文件统一管理：支持图片/音视频等。

- **表与字段组合**
  - 小鹅通：
    - 订单：`xiaoe_orders`（business-021）
    - 用户映射：`xiaoe_user_mappings`（business-022）
  - 文件：
    - 业务文件：`files`（business-023）
    - RuoYi 系统文件：`sys_file_info`（changelog-1）

## 8. 积分商城与订单域

- **核心业务能力**
  - 积分商城：商品定义 + 兑换记录。
  - 统一支付订单：活动/商品/身份/充值等，支持贡献点+积分+现金组合。
  - 订单明细：主商品 + 附赠服务/优惠券等。

- **表与字段组合**
  - 积分商城：
    - 商品：`point_products`（business-024）
    - 兑换记录：`point_redemptions`（business-025）
  - 支付订单：
    - 主订单：`payments`（business-026）
      - 订单号、用户、类型、金额拆分（总额/贡献点/积分/现金）+ 支付 & 退款状态。
    - 明细：`payment_items`（business-045）
      - 每个订单下的多条明细，支持商品/服务/优惠券/身份等，标记是否赠品/可转让/可帮买，以及使用状态。

## 9. 社群与关系网络

- **核心业务能力**
  - 合伙人社群：城市/主题社群，支持成员管理与统计。

- **表与字段组合**
  - 社群：`communities`（business-027）
  - 成员：`community_members`（business-028）

## 10. 身份体系（角色之外的对外身份）

- **核心业务能力**
  - 身份定义：创始人/联创/合伙人/高手/粉丝/城市主理人/合作方等。
  - 身份的权责利与价格，支持付费购买和历史记录。

- **表与字段组合**
  - 定义表：`identities`（business-043）
    - `identity_code, identity_level, name, icon, theme_color, intro, legal_text, rights_text, duties_text, benefits_text, upgrade_rules_text, price_amount, is_active`
  - 用户-身份关系：`user_identities`（business-044）
    - 支持多身份与历史：`user_id, identity_code, is_primary, status, acquired_at, expired_at, source_type, source_id`
  - 与订单的关系：
    - 身份付费可通过 `payments(order_type='IDENTITY', related_type='IDENTITY', related_id=identity_code)` + 对应的 `payment_items` 记录体现。

## 11. 行为轨迹与通知域

- **核心业务能力**
  - 全量行为埋点：用于画像与推荐、数据分析。
  - 系统通知与公告：小程序「通知」列表、站内消息。

- **表与字段组合**
  - 行为轨迹：`user_activity_logs`（business-042）
    - 覆盖登录/浏览/点赞/分享/报名等行为，记录 IP、设备、事件类型、来源对象、事件标签，以及当次积分/贡献点前后值。
  - 通知：
    - 站内通知：`notifications`（business-034）
    - 系统公告：`notices`（business-035）

## 12. 配置与数据字典

- **核心业务能力**
  - 业务配置：开关与数值参数。
  - 字典：会议平台、会议私密性、会议室类型、企微群类型等。

- **表与字段组合**
  - 业务配置：`system_configs`（business-033）
  - 字典：沿用 RuoYi 自带 `sys_dict_type` / `sys_dict_data`（changelog-1），在其中维护“会议平台/会议私密性/会议室类型/企业微信群类型”等字典项。

后续若需要加入“聊天/站内 IM（会话与送达记录）”等能力，可在本说明中增加「会话域」章节，并补充 `chat_threads / chat_messages / chat_message_receipts` 等表设计，与现有 `notifications` 解耦。
