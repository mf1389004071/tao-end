# 前后端国际化多语言方案分析

> 分析时间：基于当前代码库静态分析  
> 项目：十倍好智慧成长平台（tao-end / tao-pc / tao-app）

---

## 一、结论概览

| 端       | 是否有方案     | 位置/技术栈 | 多语言支持情况 |
|----------|----------------|-------------|----------------|
| **后端** | ✅ 有          | Spring MVC 消息 + SessionLocaleResolver | 已配置，仅存在**默认语言资源**（无 en/zh_CN 等分文件） |
| **管理端 tao-pc** | ⚠️ 仅 UI 组件语言 | Element Plus 固定 zh-cn | **无业务级 i18n**，界面文案为中文硬编码 |
| **小程序 tao-app** | ⚠️ 依赖与组件级 | vue-i18n 依赖存在，未在应用入口挂载；uni 组件用 @dcloudio/uni-i18n | **无应用级 i18n**，业务文案未做多语言 |

---

## 二、后端（tao-end）

### 2.1 配置与入口

- **配置类**：`geek-framework/src/main/java/com/geek/framework/config/I18nConfig.java`
  - `LocaleResolver`：`SessionLocaleResolver`，默认语言为 `Constants.DEFAULT_LOCALE`（`Locale.SIMPLIFIED_CHINESE`）
  - `LocaleChangeInterceptor`：通过请求参数 **`lang`** 切换语言
  - 拦截器已注册到 Spring MVC

- **资源路径**：`application.yml` 中 `spring.messages.basename: i18n/messages`
  - 资源目录：`geek-admin/src/main/resources/i18n/`
  - 当前仅有：**`messages.properties`**（无 `messages_zh_CN.properties`、`messages_en.properties` 等）

### 2.2 消息获取方式

- **工具类**：`geek-common/src/main/java/com/geek/common/utils/MessageUtils.java`
  - 使用 Spring `MessageSource` + `LocaleContextHolder.getLocale()` 解析消息
  - 调用方式：`MessageUtils.message(code, args)`

- **使用场景**（部分）：
  - 登录/注册/登出：`SysLoginService`、`SysRegisterService`、`LogoutSuccessHandlerImpl`（如 `user.login.success`、`user.password.not.match` 等）
  - 密码重试与锁定：`SysPasswordService`（如 `user.password.retry.limit.exceed`）
  - 异常消息：`BaseException.getMessage()` 通过 `MessageUtils.message(code, args)` 解析

### 2.3 资源文件内容概要

`i18n/messages.properties` 当前包含（均为中文）：

- 错误与校验：`not.null`、`user.jcaptcha.error`、`user.password.not.valid` 等
- 用户与登录：`user.not.exists`、`user.blocked`、`user.logout.success` 等
- 文件上传：`upload.exceed.maxSize`、`upload.filename.exceed.length`
- 权限：`no.permission`、`no.create.permission` 等

### 2.4 后端小结

- **有完整 i18n 机制**：Session 语言 + `lang` 参数 + MessageSource + MessageUtils。
- **实际仅一套语言**：只有默认 `messages.properties`，未按 `messages_zh_CN.properties` / `messages_en.properties` 拆分，扩展英文等需新增对应文件并在前端/请求中传 `lang`。

## 三、管理端（tao-pc）

### 3.1 现状

- **Element Plus 语言**：`src/components/index.ts` 中固定使用 `element-plus/dist/locale/zh-cn.mjs`，仅影响 Element Plus 组件（如日期、分页等）的文案，**非业务多语言**。
- **Flowable 流程设计器**：`src/modules/flowable/components/Process/lang/zh.js` 仅用于 bpmn-js 中文界面，属组件内部 i18n。
- **业务界面**：未发现 vue-i18n、createI18n、`$t()`、`useI18n()` 等使用；菜单、按钮、表格、表单等文案为**中文硬编码**。

### 3.2 结论

- **无统一业务级多语言方案**；若要做管理端 i18n，需新增 vue-i18n（或等价方案）及语言包，并与后端 `lang` 或用户偏好联动。

---

## 四、小程序/多端（tao-app）

### 4.1 依赖

- `package.json` 中有 **vue-i18n@^9.1.9**。
- **应用入口** `src/main.js` 中**未**创建或挂载 vue-i18n 实例，即**未做应用级 i18n 初始化**。

### 4.2 uni_modules 组件

- 部分 uni 官方/扩展组件使用 **@dcloudio/uni-i18n** 与各自目录下的 `i18n/index.js`（如 uni-search-bar、uni-popup、uni-datetime-picker、uni-calendar、uni-load-more 等），提供 en / zh-Hans / zh-Hant 等，仅影响**这些组件自身**的文案。

### 4.3 结论

- **业务层无统一多语言**；vue-i18n 未接入，业务文案未做 i18n。若要做小程序/多端 i18n，需在 `main.js` 中挂载 vue-i18n 并统一维护语言包，并可考虑与后端 `lang` 或本地设置同步。

## 六、若要扩展多语言时的建议

1. **后端**  
   - 增加 `messages_en.properties`（及按需的 `messages_zh_CN.properties`），与现有 key 保持一致。  
   - 前端/客户端在请求中带 `lang` 参数（或 Cookie/Header），与现有 `LocaleChangeInterceptor` 的 `paramName="lang"` 一致。

2. **tao-pc**  
   - 引入并配置 vue-i18n，建立 `lang/zh-CN.js`、`lang/en.js` 等。  
   - 将菜单、按钮、表格、表单等文案改为 `$t('key')` 或 `useI18n().t('key')`，并与后端 `lang` 或用户设置同步。

3. **tao-app**  
   - 在 `main.js` 中 `createI18n` 并 `app.use(i18n)`，统一语言包目录。  
   - 业务页与组件使用 `$t()` / `useI18n()`，语言切换可写存储并与后端 `lang` 或接口约定一致。

4. **前后端约定**  
   - 统一语言码（如 zh_CN、en），管理端/小程序切换语言时同步到后端（如登录后请求头或用户配置中的 `lang`），以便接口返回的提示、错误信息与前端当前语言一致。
