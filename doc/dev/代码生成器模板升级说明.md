# 代码生成器模板升级说明

## 概述

Geek-Module-Generator 模板已对齐当前项目（tao-end）最新实现，主要参考 `geek-system` 下 `SysConfig` 相关套件，并完成以下调整。

## 后端模板变更

### 1. Domain（domain.java.vm）

- 使用 **MyBatis-Flex**：`@Table("表名")`、主键 `@Id`。
- 使用 **Lombok**：`@Data`、`@EqualsAndHashCode(callSuper = true)`，不再手写 getter/setter。
- 继承 `BaseEntity`（单表/主子表）或 `TreeEntity`（树表）。
- 保留 `@Schema`、`@Excel` 等注解，与现有实体风格一致。
- **表字段 → Java 类型** 由 `GenUtils.initColumnField` 与 `GenConstants` 统一映射，日期时间统一为 `java.util.Date`，格式由 `@JsonFormat` 与 `getDateFormatPattern()` 推导，保证生成代码符合项目规范（见下表）。

### 2. Mapper（mapper.java.vm）

- 仅继承 `BaseMapper<Entity>`，无自定义方法；CRUD 由 MyBatis-Flex 提供。

### 3. Mapper XML（mapper.xml.vm）

- 仅保留 `resultMap`，不再生成 select/insert/update/delete 语句，与 Flex 注解方式配合。

### 4. Service 接口与实现（service.java.vm / serviceImpl.java.vm）

- 接口继承 `IService<Entity>`，提供：`page(entity, pageNum, pageSize)`、`export(entity, response)`、`removeByIds(ids)`；树表增加 `list(entity)`。
- 实现类继承 `ServiceImpl<Mapper, Entity>`，使用 `QueryChain` 构建查询条件，分页使用 `Page.of(pageNum, pageSize)`，与 `SysConfigServiceImpl` 风格一致。

### 5. Controller（controller.java.vm）

- 分页：使用 `TableSupport.buildPageRequest()`、`service.page(...)`、`getDataTable(list)`。
- 权限：保留 `@PreAuthorize("@ss.hasPermi('xxx:list')")` 等注解。
- 日志：保留 `@Log`、`BusinessType`。
- 入参：`@Validated @RequestBody`，`setCreateBy`/`setUpdateBy(getUsername())`，与 `SysConfigController` 一致。

## 权限与菜单：Liquibase 替代 SQL 文件

### 原行为

- 生成 `xxxMenu.sql`，需手动执行或单独导入。

### 现行为

- 不再生成 `.sql` 文件。
- 生成以下三类文件（需放到 **geek-admin** 的 `src/main/resources` 下，以便启动时被 Liquibase 加载）：
  1. **db/changelog/changelog-2-gen-{模块}-{业务}-menu.xml**  
     - 两个 changeSet：`loadData` 导入 `sys_menu`、`sys_role_menu` 的 CSV。
  2. **db/data/sys_menu_gen_{模块}_{业务}.csv**  
     - 一条菜单行 + 五条按钮行（查询/新增/修改/删除/导出），权限标识与 Controller 上 `@PreAuthorize` 一致。
  3. **db/data/sys_role_menu_gen_{模块}_{业务}.csv**  
     - 将上述 6 个 menu_id 授权给角色 `role_id=1`（管理员）。

项目启动时，Liquibase 会执行 `db/changelog` 下所有 `changelog-*.xml`（含上述生成文件），从而**自动导入菜单与权限配置**，无需再手工执行 SQL。

### 生成路径建议

- 使用「自定义路径」生成时，将**生成路径**指向 **geek-admin** 的 `src/main/resources`（或项目根目录，且把生成出的 `db/` 拷到 `geek-admin/src/main/resources/` 下），例如：
  - `tao-end/geek-admin/src/main/resources`
- 这样生成的 `db/changelog/`、`db/data/` 会落在 classpath 的 `db/` 下，与现有 `db.changelog-master.yaml` 的 `includeAll` 一致。

### 菜单 ID 冲突

- 当前菜单与按钮使用固定起始 ID：2000、2001～2005。若多次生成或多个业务共用，可能冲突。
- 避免方式：将不同业务的生成结果放到不同 changelog/CSV 中，或在 `VelocityUtils.BASE_MENU_ID` 中调大起始值后重新生成。

## 前端模板

- **api.js.vm**：删除接口改为支持批量删除，参数为单个 id 或 id 数组，路径为 `/${ids}`，与后端 `@DeleteMapping("/{ids}")` 一致。
- Vue/UniApp 等页面模板未做结构性变更，仅后端与菜单生成方式按上述调整。

## 表字段与 Java 类型映射

导入表结构时，列类型会按以下规则映射为明确的 Java 类型，保证生成实体、Service 与项目现有风格一致：

| 数据库类型 | Java 类型 | 说明 |
|-----------|-----------|------|
| char, varchar, nvarchar, varchar2, tinytext, text, mediumtext, longtext | String | 长度 ≥500 或文本类型生成 textarea |
| date | Instant | 存 UTC，序列化 ISO-8601 |
| time | Instant | 存 UTC |
| datetime, timestamp, timestamptz | Instant | 对应 timestamptz，存 UTC |
| bit, tinyint(1) | Boolean | 常见布尔/标志位 |
| tinyint(n), smallint, mediumint, int, integer | Integer | |
| bigint | Long | |
| float, double | Double | |
| decimal, numeric | BigDecimal | |
| 旧配置 LocalDate/LocalTime/LocalDateTime | Date | 兼容旧生成配置，实体字段统一为 Date |

- 日期时间统一使用 `java.util.Date`，与 `BaseEntity` 一致；导入包为 `java.util.Date`、`com.fasterxml.jackson.annotation.JsonFormat`。
- 若需调整映射（如某表希望 `tinyint(1)` 生成 Integer），可在导入后于「代码生成」编辑列属性中的「Java 类型」后保存再生成。

## 主子表（TPL_SUB）说明

- 当前模板优化以**单表 CRUD** 与 **树表** 为主（对齐 SysConfig）。
- **主子表** 生成后，Mapper 仅含 `BaseMapper`，Service 不含子表批量插入/更新逻辑，若使用主子表需在生成后**手工补全**子表相关方法或改用单表/树表模板。
